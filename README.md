## 它解决什么（一句话）

你的软件被破解、被换机共享、授权管理靠手工 Excel——ShardVase 把这四件事
变成：**VM 混淆执行 + RSA-3072 机器绑定 + 自持签发体系**，默认完全离线、
零遥测。

## 真实运行的演示（不是示意图）

演示包是这套保护本身的完整演示（反调试 → 完整性守护 → VM 校验链 →
机器绑定授权，一次运行全走一遍）。这是它在真实构建下的输出：

```
== 反逆向保护套件演示 (Anti-Reverse Protection Demo) ==
反调试扫描: 通过
机器标识:0xb4281468e21a4033
请输入序列号:license: 1 (tier=1 expires=0)
校验通过，欢迎使用！
```

包内 `license.txt` 绑定签发机——**在你的机器上首次运行会被拒绝**，
这正是机器绑定在按设计工作（机器标识会照常打印，供你申请授权）。

现在请你对它做这些——**每一条都会失败**：

| 你试一下 | 结果 |
|----------|------|
| 改 license 任意一个字符 | `license: 0`，拒绝运行 |
| 把授权拷到另一台电脑 | 拒绝（绑定在签名载荷里，文本只是说明）|
| 换掉 vm.blob（伪造/篡改）| VM 镜像装载失败 |
| 输入错误序列号 | `序列号无效。` exit=1 |
| 调试器附加 | 反调试多维检测 |

## 能力速览（每条都有证据）

| 能力 | 说明 |
|------|------|
| VM 混淆执行 | 自定义字节码引擎 + 跨构建变异；引擎函数运行期原位加解密，明文窗口=活动周期 |
| 多因子反调试 | PEB/断点/内核/时序/堆标志；干净环境零误报基线 |
| 完整性守护 | 4 组 CRC 基座（.text/.rdata/.pdata/保护节）+ 每构建随机覆盖 + 链式折叠（改一处须重算整链）+ 看门狗周期复查（含授权数据冗余校验）|
| 机器绑定授权 | RSA-3072；serial/tier/到期/机器码全部卷入签名，改一个字节即失效 |
| 防镜像替换 | VM 镜像包与授权同私钥签名；黑名单（吊销）亦签名 |
| **业务函数自动 VM 化** | 业务源一行标注 `// @vmcalc` → 构建时自动翻译进 VM 执行（A2，2026-08-29 落地）|
| 自持签发体系 | 私钥只在你的服务器；防重放；台账哈希链防静默篡改；离线签发 |
| 接入向导 | prot_sdk：三步接入（生成工程 → 写业务 → 构建+授权闭环）|

## 快速开始（3 分钟）

1. 下载[演示包](https://github.com/auui-LDAH/ShardVase-demo/releases)（v1.2.0，演示授权绑定签发机）；
2. 解压后运行 `demo.exe --vm-blob vm.blob --license-file license.txt`——
   在非签发机上首跑会因机器绑定被拒（这正是绑定在工作，机器标识照常打印）；
3. 开 [Issue：评估申请](../../issues/new?template=eval.yml)附上机器标识，
   我们签发绑定你机器的 `license.txt` 与序列号；
4. 拿到后按上面的表格动手"破坏"它——验证保护是真的。

## FAQ

**Q: 和 XProtect/Themida 比怎么样？**
A: 我们的定位不同：不只卖"壳"，而是保护+授权+签发+审计的一体化，且
源码可以给你的开发机接入调试。适用 C/MSVC x64 生态。

**Q: 会不会被杀软误报？**
A: 自修改/加密类程序天然容易触发行为检测。我们有发布版收敛策略与
申诉流程；正式使用建议配代码签名证书（这是行业通例，非缺陷）。

**Q: 离线方案能在线吗？**
A: 默认完全离线；在线签到/实时吊销是可选模块（客户自己的端点），
当前未发布。

**Q: 你能承诺"不破解"吗？**
A: 不能，也不建议任何方案这样做。我们能给的是：攻防档案、诚实边界、
持续更新。
